후원 페이지 개발 단계 구현 계획

디자인 단계에서 결정된 기능 중, 실제 개발 시 PG(결제대행) 연동이 필요한 항목을 정리한 문서입니다.

1. 문서 목적

현재 후원 페이지 디자인에는 이번달 후원 현황 바, 후원자 담벼락, 자유 금액 후원, 후원 완료 안내 기능이 포함되어 있습니다. 이 중 일부는 정적 디자인만으로는 구현이 불가능하고, 실제 결제 시스템(PG) 연동이 필요합니다. 이 문서는 어떤 기능이 어떤 방식으로, 어떤 절차를 거쳐 개발 단계에서 구현될 수 있는지를 정리한 참고용 계획서입니다.

3. 현재 운영 방식과 후원 탭의 목적

와플래시는 현재 개인이 운영하는 프로젝트로, 후원 역시 사업자 계약 없이 카카오페이·토스 개인 간 송금으로 받고 있습니다. 그러다 보니 후원해주신 분들께 감사한 마음을 전하기 위해, 매달·매년 후원자 성함을 사이트에 직접 하나하나 수기로 기재해온 것이 지금까지의 방식이었습니다. 이 과정에서 후원자들은 송금 시 입금자명을 본인 이름 대신 짧은 응원 메시지로 바꿔 보내는 방식으로 마음을 전해주고 계셨습니다.

이번 후원 탭 리뉴얼의 목적은 이 방식을 없애는 것이 아니라, 이미 자연스럽게 이루어지고 있던 이 관행을 더 편하고 깔끔하게 정리하는 데 있습니다. 수기로 명단을 옮겨 적는 대신, 후원자가 직접 담벼락에 메시지를 남기고 그 메시지가 곧바로 사이트에 반영되는 형태로 만들고자 한 것이 후원자 담벼락 기능의 출발점입니다.

• 담벼락에 방명록을 남기는 행위를 "후원 완료"와 연결지으려면(즉, 실제로 후원한 사람만 메시지를 남길 수 있도록 하려면) 결제가 끝났다는 신호를 사이트가 직접 받아야 합니다. 지금의 개인 송금 방식으로는 이 신호를 받을 방법이 없어, 이 기능은 PG 연동 이후에 구현이 가능합니다.

4. 왜 PG 연동이 필요한가

현재처럼 카카오페이·토스 개인 QR/링크로 받는 방식은 "개인 간 송금"과 동일한 구조라, 결제가 끝났다는 신호를 사이트로 보내주는 기능이 없습니다. 그래서 결제 금액을 자유롭게 입력하게 하거나, 결제 완료 시 자동으로 모달을 띄우는 것은 물론, 후원자가 실제로 결제를 완료했을 때만 담벼락에 메시지를 남기도록 하는 것까지 — 사이트와 결제 과정이 연결되는 모든 기능은 PG(결제대행사) 연동을 통해야만 가능합니다.

• PG 연동을 위해서는 사업자 등록이 선행되어야 합니다. 지금은 개인 프로젝트 단계라 사업자 등록까지 진행하기는 어려워, 이번 리뉴얼에서는 해당 기능들을 실제 구현 대상에서 제외하고 계획만 세워둔 상태입니다.

5. 자유 금액 후원 — 구현 방식

  • 결제 요청 시 금액(amount)을 고정값이 아닌 변수로 전달하는 구조로 설계
  • UI는 프리셋 금액 버튼(1,000 / 3,000 / 5,000 / 10,000원) + "직접 입력" 옵션 조합 권장
  • 최소/최대 금액 제한을 프론트엔드에서 1차 검증
  • 서버에서 결제 승인 API 응답의 실제 결제 금액을 기준으로 2차 검증 (브라우저에서 보낸 값을 그대로 신뢰하지 않음)

6. 후원 완료 모달 & 담벼락 연동 — 구현 방식

  • 결제 성공/실패 시 이동할 리다이렉트 URL(successUrl / failUrl)을 PG사에 미리 등록
  • successUrl로 돌아온 시점에 전달받은 결제 정보를 읽어 감사 모달을 자바스크립트로 표시
  • 같은 시점에 결제 승인 정보(결제 성공 여부, 주문번호 등)를 서버로 전달해, 해당 주문에 한해서만 담벼락 메시지 입력 폼을 열어주는 방식으로 연동
  • 모달 표시·담벼락 입력 허용과 별개로, 서버에서 결제 승인 API를 한 번 더 호출해 실제 결제 확정 여부를 검증

7. 사업자 등록 & PG 연동 절차

  1. 사업자 등록홈택스 또는 세무서에서 사업자 등록. 온라인 결제를 받는 경우 통신판매업 신고가 함께 필요할 수 있음. 개인사업자로 충분.
  2. PG사 선택카카오페이·토스를 개별 계약하는 대신, 포트원(구 아임포트) 또는 토스페이먼츠처럼 여러 결제수단을 한 번에 지원하는 PG사 이용 권장.
  3. 가맹점 계약 신청 및 심사사업자등록증, 서비스 화면 등을 제출해 심사 진행. 통상 며칠~2주 소요. 심사 전 테스트 연동은 미리 가능.
  4. API 키 발급클라이언트 키(프론트엔드용)와 시크릿 키(서버용) 발급. 시크릿 키는 프론트엔드에 절대 노출 금지.
  5. 결제창 연동PG사 SDK를 후원 페이지에 삽입, 후원 버튼 클릭 시 결제창(팝업/리다이렉트) 호출.
  6. 리다이렉트 URL 설정결제 성공/실패 시 돌아올 URL을 등록. 이 지점이 "후원 완료 모달"이 뜨는 지점.
  7. 성공 페이지 처리전달받은 결제 정보로 모달 표시 + 서버 측 결제 승인 검증 로직 구현.
  8. 테스트 후 전환테스트 모드로 전체 흐름 검증 후, 가맹 심사 통과 시 실 서비스 키로 교체.

8. 그 외 참고 사항

주의할 사항
PG사마다 결제 가능한 최소 금액, 수수료율, 정산 주기가 다르므로 실제 계약 전 비교가 필요합니다. 또한 개인 정보(후원자 닉네임, 메시지 등)를 저장하는 담벼락 기능은 별도의 개인정보처리방침 명시가 필요할 수 있습니다.
